## Зачем

Определения → дерево → unit → 3 сценария. Агент считает; **человек калибрует**. Числа — свои (факт или честные допущения), не копия Ритма.

---

## Задачи

### A. Определения (≈45–60 мин)

`metrics/DEFINITIONS.md` — таблица:

| Метрика | Формула | Окно | Дедуп | Источник (`live`/`assumption`) |
|---|---|---|---|---|

Правило: агент **не** меняет определения без вашего diff в этом файле.

### B. Дерево (≈60–90 мин)

`metrics/tree.md` (можно mermaid):

1. North Star наверху.  
2. 4–8 драйверов.  
3. Рычаги: продукт / канал / монетизация.  
4. Ссылки на H__ там, где пересечение с гипотезами (или явно «вне дерева»).

### C. Unit economics (≈60–90 мин)

`metrics/unit.md` на **одну** единицу (user / org / заказ):

- Выручка на единицу (proxy ok).  
- Переменные затраты.  
- Contribution margin proxy.  
- CAC / payback — если нет данных: секция `UNKNOWN` + план замера.  
- Связь с tornado Н4 (те же допущения или объяснение различий).

### D. Три сценария + калибровка (≈90–120 мин)

1. `metrics/scenarios.md`: Downside / Base / Upside по ключевым драйверам + итог.  
2. Протокол с агентом: дать DEFINITIONS + tree + допущения → попросить таблицу.  
3. **Калибровка:** измените ≥2 числа вручную; `metrics/CALIBRATION.md` — что агент завысил/занизил и почему.

Опционально: один spreadsheet + README со ссылками вместо трёх MD — ок, если те же блоки.

### E. Чтение (≈30 мин)

Шпаргалки метрик/юнита из `itmo-product-analytics` · Ритм unit как *паттерн* · pm-skills analytics skim.
