# Н5 · Lesson outline — Дерево метрик, юнит, финмодель

| Поле | Значение |
|---|---|
| **Неделя** | 5 · ~1,5 ч + 4–6 ч практика |
| **Артефакты** | Дерево метрик · unit economics · 3 сценария (base/upside/downside) |
| **Демо instructor** | Эталон дерева Ритма |
| **SUL** | Дожим S3 при необходимости; подготовка метрик к S4 |

---

## Цели

1. Построить **дерево метрик** своего продукта (North Star → драйверы → рычаги).  
2. Собрать **unit**-модель: на единицу (user/order/seat) — вклад, затраты, payback-proxy.  
3. Прогнать **3 сценария**; агент считает, **человек калибрует** допущения.  
4. Не повторять курс аналитики с нуля — опираемся на прошлые репо как шпаргалки.

---

## Теория коротко

### 1. Агент считает — человек отвечает за определения

```mermaid
flowchart LR
  Def[Человек: определения метрик] --> Ctx[Контекст-файлы]
  Ctx --> Agent[Агент: считает сценарии]
  Agent --> Cal[Человек: калибровка]
  Cal --> Art[Дерево + unit + 3 сценария]
```

### 2. Дерево

North Star → input metrics → рычаги продукта/роста. Каждая стрелка = гипотеза влияния (можно сослаться на H__).

### 3. Unit

Минимум: contribution margin proxy, CAC proxy (если есть), payback/период окупаемости или «не считаем CAC — честно». Лучше честный gap, чем выдуманный CAC.

### 4. Стык с SUL

Метрики Z из гипотез должны быть узлами дерева или явно «вне дерева (претест)».

Опора: `itmo-product-analytics` · Ритм М1.3 · pm-skills analytics.

## Тайминг

| Мин | Блок |
|---|---|
| 0–10 | Определения: что студенты путают (retention window) |
| 10–40 | Live дерево Ритма + unit на демо-числах |
| 40–60 | Калибровка: агент предложил CAC — человек ломает |
| 60–80 | Workshop: студент вставляет свой NS |
| 80–90 | Связь с S3 tornado |
