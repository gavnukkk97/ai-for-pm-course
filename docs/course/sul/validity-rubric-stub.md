# Рубрика валидности симуляции (stub → S5)

Использовать в decision memo и на защите. **Честность > «прокрас».**

Шкала: `0` нет · `1` слабо · `2` достаточно · `3` сильно (с калибровкой).

## A. Дизайн

| Критерий | 0–3 | Комментарий |
|---|---|---|
| Гипотеза в форме X→Y→Z, метрика определена до прогона | | |
| Between-subject (нет памяти агента между вариантами) | | |
| N агентов ≥ заявленного порога недели (S4: 50–100) | | |
| Seed / модель / temperature зафиксированы | | |
| Артефакт теста = тот же, что у живых пользователей (URL/экран) | | |

## B. Персоны

| Критерий | 0–3 | Комментарий |
|---|---|---|
| ≥3 сегмента, нет «среднего пользователя» | | |
| Поля схемы заполнены (JTBD, constraints, channels) | | |
| Персоны опираются на данные/интервью/кластеры, не только на LLM | | |
| Известные смещения перечислены | | |

## C. Внешняя валидность

| Критерий | 0–3 | Комментарий |
|---|---|---|
| Калибровка на известном кейсе / прошлом живом тесте | | |
| Сонаправленность знака измерена или честно «не измеряли» | | |
| Цена ошибки решения названа | | |
| Вердикт: supports / rejects / inconclusive **без** живых людей | | |

## D. Решение

Обязательный абзац (скопируйте в memo):

> По симуляции мы бы: _______________.  
> Этого **недостаточно**, чтобы: _______________.  
> Следующий живой шаг: _______________.
