## Что выглядит хорошо

| Артефакт | Структура | Quality bar |
|---|---|---|
| ICP | кто + анти-ICP + каналы + WTP-proxy | Анти-ICP отсекает ≥1 соблазнительный сегмент |
| Конкуренты | ≥5, типы размечены | Заменитель №1 = «ничего»/Notes/Excel, не только SaaS-пиры |
| УТП | 1 строка + ≥2 falsifiers | Falsifier проверяем (что измерим/увидим) |
| Sources | таблица claim → source → class | Не всё `llm_draft` |
| Персоны | ≥10, ≥3 segment, INDEX | Constraints + JTBD; id стабильны |

**Отлично:** 3 сегмента с разными kill-constraints; sources смесь desk/live.  
**Достаточно:** 10 персон, 3 сегмента, sources с assumption-метками.  
**Недостаточно:** 10 клонов одного сегмента с разными именами.

---

## Частые провалы

| Симптом | Ремедиация |
|---|---|
| ICP = весь рынок | Спросить: «кого *не* берём в S1?» |
| Нет заменителя «ничего» | Добавить строку в competitors |
| Персоны только из LLM | Требовать sources.md + 1 desk/live claim на сегмент |
| Скопирована Аня из примера в B2B | Вернуть: структура schema, свои JTBD |
| УТП без falsifiers | «Как узнаем, что УТП ложно?» |
| Нет плана ≥15 к Н3 | Записать в INDEX |

## Чеклист оценки

### Research (0–4)
- [ ] icp с анти-ICP  
- [ ] ≥5 конкурентов/заменителей  
- [ ] УТП + falsifiers  
- [ ] sources с метками  

### Personas (0–4)
- [ ] ≥10 файлов  
- [ ] ≥3 segment  
- [ ] INDEX актуален  
- [ ] Нет «среднего пользователя» без JTBD  

**Pass:** research ≥3 и personas ≥3.  
**Rework:** копия Ритма 1:1 или пустой sources.
